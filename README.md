# 植物标本馆 · 补照工作台

压制标本入库前的补照管理工具：登记标本 → 压制完成进入补照队列 → 齐三类照片 → 鉴定通过 → 分配柜位上柜。数据（含照片）全部保存在浏览器 IndexedDB，关闭重开可继续处理。

## 工作流程

1. **登记 / 压制**：录入采集号、物种、采集地点、海拔、生境、采集人；可勾选「压制已完成」直接入队，未完成的留在压制跟踪区一键完成。采集号重复即时提示。
2. **补照队列**：每份标本需留齐 **整株 · 标签 · 生境** 三类照片，缺一类即留在队列（可按缺照 / 退回待改 / 待鉴定筛选，另支持关键词搜索）。拍摄人可直接在卡片内补拍上传（手机端可调起相机）。
3. **退回修改**：发现物种名或采集号有误时可退回，必须填写退回原因；标本回到队列，**旧照片全部保留**，原因挂在卡片与详情页；修改信息后退回意见自动标记已处理，全程记入处理流水。鉴定通过后发现问题同样可退回（撤销通过、照片保留）。
4. **鉴定筛选**：只有三类照片齐全且无未处理退回意见的标本才能鉴定通过，通过后进入待上柜；支持按采集地点下拉筛选。
5. **柜位记录**：按「柜号-层-位」（如 A-12-03）分配；**柜位已被占用时仅提示换位，原队列与柜位记录不变**，不写入任何数据。
6. **地点信息卡**：按采集地点汇总海拔、采集人、各阶段标本数，可展开查看该地点全部标本。
7. **详情页**：登记信息、三类照片、退回记录、完整处理流水、照片大图；URL 为 `#/specimen/<id>`，可收藏/分享。

队列、鉴定筛选、地点信息卡、柜位记录与详情页读同一份 IndexedDB 数据，实时联动。照片上传时自动压缩（长边 1600px / JPEG 0.82）以节省本地配额。

## 技术栈

React 19 + Vite 7 + TypeScript，零额外运行时依赖；存储为浏览器 IndexedDB（记录与图片 Blob 同库）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62007（http://localhost:62007）

首次打开会写入一批内置演示标本（含缺照、退回、待鉴定、已上柜等状态）；页脚可重置演示数据，不会产生重复记录，用户自行登记的标本保留。

## 生产构建

```bash
npm run build && npm run preview
```
