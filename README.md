# 植物标本馆 · 补照工作台

压制标本入库前端：登记采集信息 → 压制完成进入补照队列 → 补齐整株 / 标签 / 生境三类照片 → 鉴定通过后上柜。退回修改保留旧照片与退回原因；柜位冲突时提示换位且不改动任何记录。

## 功能

- **标本登记**：采集号、物种、采集地点、海拔、生境、采集人六项必填，采集号全库唯一；压制状态分「未压制 / 压制中 / 压制完成」，只有压制完成才进补照队列。
- **补照队列**：每份标本须留整株、标签、生境三类照片（可多张、可预览、可删除），少一类时「提交鉴定」按钮禁用并提示缺哪类，强制留在队列。
- **退回修改**：拍摄人发现物种名或采集号等写错时可退回（队列卡片、详情页均可），退回原因留档、已有照片全部保留；改完字段后照片仍齐全才能重新送鉴定，字段差异记录在时间线中。
- **鉴定筛选**：只显示补照齐全并提交鉴定的标本，可按采集号 / 物种 / 地点筛选；鉴定通过时指定柜位。
- **柜位记录**：柜位号（大小写不敏感）已被占用时即时提示占用标本并要求换位，领域层最终校验，冲突时队列与柜位表均不写入；上柜后生成柜位记录。
- **地点信息卡**：按采集地点自动归并，汇总海拔、生境、采集人、涉及物种与各标本阶段 / 补照进度。
- **单份详情页**：六项登记信息、三类照片、退回修改记录（旧值→新值）、完整处理时间线。
- **同一份浏览器数据**：所有视图与详情页读写同一份 localStorage（`herbarium-workbench:v1`），重开浏览器接着处理；写入失败（如配额已满）整体回滚并提示。
- 顶栏可切换当前工作人员（登记 / 压制 / 拍摄 / 鉴定 / 上柜操作均记录经手人）；内置「载入演示数据」可一键体验全流程。

## 技术栈

React 19 + Vite + TypeScript，纯前端，无后端。工作流为纯函数状态机（`src/domain.ts`），界面层只负责调用，关键规则有领域测试与 jsdom 端到端测试覆盖。上传图片在浏览器内压缩为最长边 1400px 的 JPEG 后再存 localStorage。

## 本地运行

```bash
npm install
npm run dev        # http://localhost:62007
```

其他命令：

```bash
npm test           # 领域规则测试 + jsdom 端到端测试
npm run typecheck  # tsc 严格模式
npm run build      # 生产构建
```

## 工作流状态

```
登记(unpressed) → 压制中(pressing) → 压制完成
        → 补照队列(queue) ──缺照片则留在队列──┐
        → 待鉴定(identifying)                 │
            ├─ 退回修改(rework，保留照片/原因)─┘
            └─ 柜位可用 → 已上柜(stored)
               柜位占用 → 提示换位，记录不变
```
